> 需求原文：「给格斗系统添加一个『闪避 / 格挡』的操作，只要能提供更强的操作空间；这些说明要加进游戏规则里。」

## 0. 先查证：现有防御层到底是什么（不是猜测）

| 事实 | 证据 |
| :--- | :--- |
| `block` 动作**已经存在**（站防），`crouch` 兼具蹲防 | `src/rules.js:28` ACTIONS；`src/engine.js:184` `if (action === 'block') f.state = 'guard'` |
| 防御高度裁定集中在一个纯函数 | `src/combat.js` `guardResult()`：站防被 `low` 破、蹲防被 `high`/`overhead` 破、`throw` / `unblockable` 无视防御 |
| 防御不是无代价：吃削血 + blockstun，自己是劣势帧 | `src/engine.js` `applyDamage()` block 分支：`chip = max(1, dmg/10)`，`def.blockstun = hb.blockstun`，防守方只回 4 气 |
| **当前没有任何「完全躲开一次判定」的手段** | `invuln` 只来自 `dp`(3) / `ex`(2) / `super`(6) / 起身(8)，全部绑定在**进攻动作**的起手帧上，不能当防御用 |
| kit 里已有一个叫「当身 (parry stance)」的原型，语义是**换伤**不是**免伤** | `src/kits/counter.js` 头注释 + `resolveCounter()`：吸收一次近身判定并打出 `spec.damage`，对飞行道具 / 投技无效，**不给气** |
| 现有防御验收覆盖 K9 / K10 / K11 / K28 / K29 | `scripts/verify-combat.mjs`，本次为回归边界，不得改动其期望值 |

**结论：需求缺的不是 `block`，而是 `block` 之上的两层主动防御。** 因此本次落为两个新动作：

- `dodge` 闪避 —— 时空规避：无敌帧 + 后撤位移，能穿过拳脚和飞行道具，**被投技破**，有冷却。
- `parry` 招架（精准格挡）—— 读判定：窗口内把任意可防高度的攻击**完全无效化**（零削血、零硬直）并回大条气，**被投技破**，空挥代价大。

与已有 `当身 (counter)` 的分工写进规则文档，避免角色混淆：counter = 一个**招式**（占技能位、换伤害、窗口 = 其 active 帧）；parry = 一个**全员防御动作**（不换伤害、只回气、窗口 8 帧、空挥 16 帧破绽）。

## 1. Test scope contract

### 1.1 用户目标

给策略作者打开「不吃这一帧」的操作空间：从「站防被磨血 / 蹲防被高段择」的二元，扩到 block / crouch / parry / dodge 四元，并且四种读法各自有明确破解手段；**同时这套相克关系必须以数据形式出现在游戏规则里**（`get_rules` / `/api/rules` / 对外文档），不是只写在 commit message 里。

### 1.2 明确非目标

- **不改** 已有招式的帧数据、伤害、取消梯子、气槽经济、命中停顿、击倒/起身规则。
- **不改** 匹配、ELO/榜单、计费口径、回放 JSONL 格式、MCP 工具面（只扩数据，不加新工具）。
- **不改** `src/agents.js` 官方基线与 `src/training.js` 训练假人的行为（新动作对 baseline 保持不可用/不使用，榜单强度不漂移）。
- **不做** 逐帧新美术：`dodge` / `parry` 的画面上由权威骨架 pose 驱动，接受程序化姿态。
- **不做** 浏览器级截图验收（verify:art / verify:render 只要求不回归）。
- 不引入第二个「防御高度」真相源（不许在 engine 里再写一份 if）。

### 1.3 范围内行为（拟定契约，数值是验收对象本身）

`src/config.js` 新增（全部整数，保持定点确定性）：

```
DODGE_ACTIVE: 10    DODGE_RECOVERY: 8     DODGE_BACK_VX: 5   // 后退 50 单位
DODGE_INVULN: 10    DODGE_COOLDOWN: 30    DODGE_METER: 15
PARRY_ACTIVE: 8     PARRY_RECOVERY: 16    PARRY_METER: 25
RULES_VERSION: '2.0' -> '2.1'
```

`src/rules.js` MOVES 新增两条 `kind: 'defense'`（`dodge` / `parry`），ACTIONS 由 19 → 21。结算契约（本表即 `get_rules().defensive` 的内容）：

| 来袭 | `block` 站防 | `crouch` 蹲防 | `parry` 招架 | `dodge` 闪避 |
| :--- | :--- | :--- | :--- | :--- |
| `low` 拳脚 | **破**（吃满伤害） | 挡住（削血） | 无效化 + 25 气 | 穿过 + 15 气 |
| `mid` 拳脚 | 挡住（削血） | 挡住（削血） | 无效化 + 25 气 | 穿过 + 15 气 |
| `high` / `overhead` | 挡住（削血） | **破** | 无效化 + 25 气 | 穿过 + 15 气 |
| 飞行道具 | 挡住（削 6） | 挡住（削 6） | 消弹 + 25 气 | 穿过 + 15 气 |
| `throw` / `unblockable` | **破** | **破** | **破** | **破**（`breaksDodge`，无视闪避无敌） |

风险/收益条款（同样要进规则数据）：

1. `parry` 的空挥惩罚：窗口 8 帧过后进入 16 帧 recovery，此期间**不处于任何 guard 状态**，被打中吃全额伤害（不是削血、不是 blockstun）。
2. `dodge` 的无敌只有前 10 帧，后 8 帧可被抓；且落 cooldown 30 帧，期间 `dodge` 输入不启动（对齐 `canAfford` 的「不消耗、下拍可重发」语义）。
3. 两者都**不能取消**（不进 `cancelInto` 梯子），也不能被 `dash` 取消出来——它们是独立决策，防止变成连段补丁。
4. 观察面必须把可读信息给全：`self.dodgeCooldown`、`self.parryActive`、`derived.threat` 不变、`legalActions` 含两个新动作；否则策略无法利用，验收直接算失败。
5. 事件流必须落 `evade` / `parry` 两类事件（HUD、回放、训练场归因共用一份），字段含 `frame/by/on/move/absorbed/meterGain/x/y`。

### 1.4 范围外行为（明确不许顺带改）

- 命中判定仍是骨架矩形 `firstOverlap`，不引入距离近似。
- `hitstop`、`wakeup`、`comboScale`、`chip` 数值不变。
- 老回放不承诺在新 `RULES_VERSION` 下复现——这是**声明**，不是 bug；但当前版本内 `replayMatch` 必须仍 `ok: true`。

## 3. 最小纵向切片

**切片：A2 + A4 —— 「同一次 `dodge`，穿过一记中段拳，但被一记投技照样抓倒。」**

为什么这一条足以代表本次目标：

- 它一次穿过全部所有权：`ACTIONS`/`MOVES`（规则表）→ `engine.tickFighter`（动作→状态与位移）→ `combat.js`（无敌/`breaksDodge` 裁定，与 `guardResult` 同域）→ `applyDamage`（结算与给气）→ `protocol.fighterView`（把 cooldown 报给策略）→ 事件流（回放/HUD/训练归因）。任何一环没接上，断言就红。
- 它同时锁住**收益**（穿过判定）和**代价**（被投技破），也就是「操作空间」这个目标的正负两面；只测其一会出现「无敌过强也算通过」的假绿。
- 它是用户/策略可直接观察的行为，不依赖任何内部计数。
- A8–A11（招架的四态）与 A14/A20（规则可读）是同一批缝上的独立断言，不需要第二个切片。
